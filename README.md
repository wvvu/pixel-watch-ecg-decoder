# Pixel Watch 2 · Fitbit ECG `ecg-*.dat` 格式说明（BIFA）

> 破解来源：`com.fitbit.ecg` 的 `libecg.so`（fb_ecg_lib / "ECGlib"）静态逆向（capstone）+ 双样本（ecg-001/002）统计验证。
> 配套脚本：`ecg_decode.py`。样本：`ecg-001.dat`、`ecg-002.dat`（两条真实 30s 录制）。

---

## 1. 文件总览

每个文件**固定 19,858 字节**，整体为：

```
┌─────────┬──────────┬──────────────────────┬────────┬──────────┐
│ Magic   │ u32 长度 │ 数据区 (19616/19624B) │ 零填充 │ 文件结束 │
│ "BIFA"  │ (LE)     │ （含 32B 尾部校验和） │ 至满长 │          │
│ 4 bytes │ 4 bytes  │                      │        │          │
└─────────┴──────────┴──────────────────────┴────────┴──────────┘
```

- `BIFA` 即 "AFIB"（房颤）反写。
- 数据区长度字段：ecg-001 = `0x4CA0`(19616)、ecg-002 = `0x4CA8`(19624)。

## 2. 数据区逐段布局（相对文件偏移）

数据区 = 文件偏移 [8, 8+data_size)，以下偏移均相对**数据区起点**（body[0]）。

| 偏移 | 长度 | 类型 | 内容 |
|------|------|------|------|
| 0x00 | 12B | bytes | 固定段 `01 02 03 01 00 41 07 00 00 00 00 00`（版本/标志，见 §4） |
| 0x0C | 1B | u8 | `00` |
| 0x0D | 4B | f32 LE | 约 94.05 / 98.59（两文件不同，语义待定，疑似心率） |
| 0x11 | 4B | u32 LE | 83 / 88 |
| 0x15 | 4B | f32 LE | 约 723.5 / 687.8 |
| 0x19 | 4B | f32 LE | 720.0 / 680.0 |
| 0x1D | 4B | f32 LE | 20.0 / 20.0（疑似录制时长配置） |
| 0x21 | 4B | f32 LE | 约 64.2 / 32.1 |
| 0x25 | 4B | f32 LE | 约 105.9 / 81.6 |
| ... | ... | ... | 元数据浮点/整数序列（含 94.05 重复出现等），未全部标注 |
| 0xDD | 4B | u32 LE | **采样数 = 7500**（代码检查 `< 7501`） |
| 0xE1 | 15000B | int16 LE | **ECG 波形：7500 个采样 @ 250Hz = 30.0 秒** |
| 0x3B79 | 4B | u32 LE | **帧计数 = 469** |
| +4 | 469×8B | u32×2 | **帧时间戳表**：每条 = (u32 微秒时间戳, u32 0)；范围约 4.69s → 34.58s，单调递增，平均间隔 63.9ms |
| —— | 603/611B | 见 §4 | **注解区**（2026-09-16 已破译，见 §4 详表） |
| 尾 32B | 32B | bytes | **校验和**：前 16B 有效 + 16B 0（keyed 算法，非 MD5/SHA1/SHA256/CRC64 裸算，疑似 domainKey 派生；不重要时可忽略） |

> 注1：ecg-002 的 data_size 比 ecg-001 大 8，差异落在**注解区**（611 vs 603B），波形与时间戳表完全一致。
> 注2：多个字段（0xDD、采样数、时间戳表）为**非 4 对齐**布局，说明是 packed struct。

## 3. 波形

- 编码：**int16 小端**，偏移数据区 0xE1 起，连续 7500 个。
- 采样率：**250 Hz**（7500 样本 / 30s；与 Fitbit ECG 公开规格一致）。
- 幅值：ecg-001 [-32768, +21637]；ecg-002 [-16873, +11985]。单位：ADC LSB（16-bit），换算 µV 需设备增益校准（未见增益字段）。
- 形态：两条录音均呈现规律 P-QRS-T 复合波；ecg-002 全程约 60+ 心搏、心率约 95–130 bpm；ecg-001 含数个大振幅深谷（至 ±32000），整体心率略低。

## 4. 注解区结构（双样本验证破译）

注解区相对**数据区起点**的偏移：`0x4A25`（= 0xE1 + 7500×2 + 4 + 469×8）。

| 区内偏移 | 长度 | 类型 | 内容 | 依据 |
|---|---|---|---|---|
| 0 | 469B | u8[] | **帧有效标志**：1 = 该 64ms 块（16 样本）有有效数据；0 = 无信号块。ecg-001 全部有效（469/469）；ecg-002 前 13 帧无效（0.83s 起手期，456/469） | 两样本对比 |
| 469 | 4B | u32 LE | `0x1D50` = 7504 = 469 帧 × 16 样本（样本位宽常量，两文件相同；独立于 n_samples） | 常量校验 |
| 473 | 18B | bytes | 全零 | 观察 |
| 491 | 12B | 3×f32 LE | **信号质量指标**：(f32①, f32②, f32③)，①+②≈1.0 互补 → ①=有效信号功率占比、②=伪影/干扰占比；③=绝对噪声水平。ecg-001 = (0.803, 0.197, 2.7e-4)——有两次接触丢失事件，质量明显低于 ecg-002 = (0.995, 0.004, 4.1e-4) | 归一化验证 |
| 503 | 2×(N+1)B | u16 LE[] | **QRS onset 序列**：每次心搏的检测触发点样本索引（0 终止），N = ecg-001 41 跳 / ecg-002 45 跳；onset 比 R 峰顶提前固定 36–40ms（9–10 样本），与波形峰值逐对验证偏差中位数 9–10 | 峰对位验证（44/45 项偏差 8–11） |
| 503+2(N+1) | 16B | bytes | 尾部元数据：含两文件公共 u32 `0x00065B8F`（=415887），语义待定 | 观察 |

### QRS onset 验证方法

对每条 onset 找波形最近 R 峰（能量包络检测），偏差分布：ecg-001 中位数 10、ecg-002 中位数 9（绝大多数 8–11）。第 0 项（40/44）为独立前导字段，非心跳（形状异常，可能为检测起点）。两条录音尾部各有 1–2 个「检测器可见但未入列」的边缘峰，恰为接触松动/伪影前的低质量心搏，符合手表检测器拒收逻辑。

## 5. 逆向依据（libecg.so 关键锚点）

| 日志/导出 | 结论 |
|---|---|
| `wrong magic number in result file` | 读文件先校验 4B magic（= `BIFA`，literal pool @0xE8C4） |
| `data size in header (%u) larger than file size` | header 内 u32 数据长，与文件大小比对 |
| `short read on header version minor v11/v12` | header 含版本字节，v1/v2 两套解析分支（v2 字段更多） |
| `CRC does not match` / `couldn't compute checksum` | 尾部 32B 校验（覆盖 data_size-32 字节，算法为 keyed hash） |
| `couldn't allocate space for ecg compressed data` | 数据区 = "压缩/精简"后的结果（即本格式） |
| `malloc(0x4D92=19858)` | 读函数按整文件大小分配缓冲 |
| `(J[F)V` 导出 | native 采集回调 `updatedData(long, float[])`，float 波形由 native 解码后给 Java |
| 0xDD 处 `cmp r1, #0x1D4D(7501)` | 采样数上限检查 → 7500 |

## 6. 未破解/待确认

1. **校验和算法**：疑似 keyed（domainKey / user_key_hash 派生），离线不可验；`rsp-*` 回包同理为 A128GCM，无密钥不解。
2. **注解区尾部 16B**：含公共 u32 `0x00065B8F`（=415887），语义待定；`ann_u32 = 7504` 的精确含义（帧数×16 或 n_samples+4）待固件确认。
3. **0x00–0xDC 元数据**：已列字段的语义（心率？增益？）未经固件确认，需对照 Fitbit App 显示值。
4. **采样率 250Hz** 由 7500/30s 推出，建议与 Fitbit App 波形比对核验。
5. **帧有效标志**的「有效」精确判据（幅值阈值？ADC 锁定检测？）未从固件确认，仅由 ecg-002 起手 0.83s 空白段反推。

## 7. 使用

```bash
python ecg_decode.py ecg-001.dat ecg-002.dat --plot --svg --compare --outdir .
```

输出：终端摘要、PNG/SVG 波形图、R 峰对齐对比图。
